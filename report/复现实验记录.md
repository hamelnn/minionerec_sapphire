## 2. SFT（方案第 4 节）

代码修改（sft.py）：`gradient_checkpointing=True`（use_reentrant=False）、`optim="adamw_bnb_8bit"`、`report_to="none"`、新增 `max_steps`/`eval_step` 参数、峰值显存打印。另修复 `data.py CSVBaseDataset.sample` 超过数据集大小时的崩溃（改为 `sample < len` 才采样）。

### 2.1 短训练（验收标准：几十步无 OOM/NaN，至少一次验证与保存）

配置：max_steps=50、eval/save 每 25 步、micro_batch=1、accum=32、cutoff=256、lr=5e-5、sample=2000。

结果：**通过**。train_loss 5.82→3.96，eval_loss 4.87，无 OOM/NaN；peak allocated 4.33 GiB / reserved 4.61 GiB；0.144 步/秒（6.95 s/优化步）；eval 52s/2000 样本。50 步 checkpoint 冒烟测试（5 个测试样本 × 20 beams）：100/100 候选全部为合法 SID（约束解码端到端正常），尚无命中（训练量极小，符合预期）。

### 2.2 正式训练

配置：micro_batch=1、batch=32、cutoff=256、lr=5e-5、epochs=3、seed=42、sample=6000/任务（全量 3 epochs 约需 14.5h，按方案第 3 节"减少训练样本数主要缩短运行时间"缩减；early stopping patience=3）。

结果：**完成**。1689 优化步（约 3 epochs），train_loss 5.8 → 1.25，best eval_loss 2.266（checkpoint-1521）。训练耗时 9237s（2.57h），峰值显存 allocated 4.33 GiB / reserved 4.61 GiB。

### 2.3 SFT 基线评测

配置：evaluate.py + calc.py + check_validity.py，4533 个测试样本，num_beams=20、max_new_tokens=16、length_penalty=0.0。

结果：**HR@1/3/5/10/20 = 5.1% / 7.2% / 8.4% / 9.9% / 13.3%**；**NDCG@1/3/5/10/20 = 5.1% / 6.3% / 6.8% / 7.3% / 8.1%**；**合法 SID 比例 100.0%，重复候选 0/4533**。SFT 已具备有效推荐能力（3686 物品中 @20 命中 13.3%）。

## 3. RL（方案第 5 节）

代码修改（rl.py）：GRPOConfig 增加 `model_init_kwargs(use_cache=False)`、`max_prompt_length=256`、`max_completion_length=16`、`use_vllm=False`、`optim="adamw_torch"`、`report_to="none"`、`save_total_limit=2`；注入 LoRA（r=16, alpha=32, dropout=0, 七个投影层）并在构造后校验 `print_trainable_parameters`（8.8M / 1.75%）与 `ref_model is None`。冗余 `llm_model` 加载在本仓库版本已按 reward_type 门控（ranking 下不加载）。trainer 增加 `group_hit_ratio` / `nonzero_adv_ratio` 指标（方案 5.5 要求）。

### 3.1 关键修复：reentrant 梯度检查点断梯度

首轮 RL 短训练报 `RuntimeError: element 0 of tensors does not require grad`。定位：PEFT 包装后底座（含 embedding/lm_head）全部冻结，而 reentrant checkpoint 只检查"函数输入"（block 的 hidden_states，来自冻结 embedding → 无梯度），判定无输入需梯度后以 `no_grad` 执行 forward → 梯度断链。尽管 GRPOConfig 传了 `use_reentrant=False`，transformers Trainer train() 内使能时仍产出 `use_reentrant=True`（transformers/PEFT 交互问题，已通过拦截确认 `GC func: use_reentrant=True`）。

修复：0.5B 模型显存充裕，RL 关闭梯度检查点（`use_gradient_checkpointing=False`，默认）。

### 3.2 RL 短训练（验收标准：仅 LoRA 可训练、ref_model=None、非零 advantage）

配置：max_steps=15、train_batch=4、num_generations=4、grad_accum=8、lr=1e-5、beta=0.001、beam_search=True、ranking reward、rl_sample=200、rl_seq_sample=200、eval_sample=100。

结果：**通过**。trainable 8,798,208 / 1.75%（仅 LoRA），ref_model=None。15 步无错误，每步 ~7.3s，峰值显存 allocated 3.10 GiB / reserved 3.41 GiB。第 13 步出现 `group_hit_ratio=0.125`、`nonzero_adv_ratio=0.125`、grad_norm=0.18 → reward→advantage→参数更新环路有效；多数步 reward=0 属奖励稀疏正常现象，kl≈0.001 与 beta=0.001 一致。

### 3.3 RL 正式训练

配置：rl_sample=2000、rl_seq_sample=2000、eval_sample=200、eval_step=0.199、1 epoch、其余同上。约 6000 prompts × 4 gens = 24000 样本 → 6000 batches → 750 优化步。

结果：**完成**。训练耗时 3513s（58min），峰值显存 allocated 3.10 GiB / reserved 3.42 GiB。最终 eval（200 样本）：`eval_group_hit_ratio=0.07`、`eval_nonzero_adv_ratio=0.07`、`eval_reward=0.0064`、`eval_kl=0.60`。4 候选在 3686 物品中命中 7% 的验证组，RL 环路有效；奖励稀疏属预期。

## 6. 与方案的偏差记录

1. peft 0.21.0 需要现场安装（环境中缺失），与 transformers 4.57.1 / trl 0.24.0 兼容。
2. SFT 正式训练使用 sample=6000/任务（全量约 14.5h 超出可执行窗口，方案第 3 节允许以样本数换时间）。
3. RL 训练使用 rl_sample/rl_seq_sample/eval_sample 缩减规模（同上）。
4. 修复 data.py 的 sample 越界崩溃（不影响 -1 全量路径）。
5. RL 关闭梯度检查点（方案 5.2 建议开启，但 PEFT+reentrant GC 在 transformers 4.57 下断梯度；0.5B 显存充裕，实测 RL 峰值仅 3.1 GiB，关闭无显存压力）。
